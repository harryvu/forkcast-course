Where we are

Lesson 12's Transformer learned word order from 40,000 reviews and gained a little over the bag. Lesson 9 showed the alternative for images: start from a network that has already learned to see. The same is true for text, more so. DistilBERT, a 66-million-parameter encoder trained on Wikipedia and books, already knows that "overpriced" is negative and "unbelievably" intensifies what follows; fine-tuning teaches it what Forkcast's customers mean by a one-star review in an hour on a free GPU. The second thing a pretrained encoder gives you is an embedding for any sentence, which turns menu search from matching words into matching meaning. The tests use a toy DistilBERT with random weights and a tokenizer trained on the bundled reviews, so they download nothing; the notebook uses the real models.

Subword tokenizers

Lesson 11's vocabulary had one id for every unseen word, and "overpriced" was unseen. A subword tokenizer learns a vocabulary of pieces, whole common words plus fragments, and splits any word into the longest pieces it knows: "over" + "##priced". Nothing is ever unknown, rare words simply cost more tokens, and a 30,522-piece vocabulary covers all of English. The tokenizer also adds a [CLS] token at the start and [SEP] at the end, pads, and returns the attention mask you built by hand last lesson. A pretrained model's tokenizer is part of the model: the ids must mean what the weights expect.

tok = AutoTokenizer.from_pretrained("distilbert-base-uncased")      # the real one; tests train a 310-piece one on our reviews
enc = tok(["Overpriced forkcast pizza, soggy fries!", "Cold."], padding=True, truncation=True, max_length=32, return_tensors="pt")
enc["input_ids"].shape, enc["attention_mask"].shape   (torch.Size([2, 18]), torch.Size([2, 18]))
tok.convert_ids_to_tokens(enc["input_ids"][0])
['[CLS]', 'over', '##p', '##ri', '##c', '##ed', 'for', '##k', '##c', '##ast', 'pizza', ',', 'soggy', 'fri', '##e', '##s', '!', '[SEP]']   the toy tokenizer

A pretrained model is an nn.Module

Everything in the transformers library is a PyTorch module. AutoModel.from_pretrained downloads the weights once and returns an encoder you can call; AutoModelForSequenceClassification adds a fresh classification head, Lesson 9's "replace the head" done for you. The forward call takes the tokenizer's dict unpacked, model(**batch), and returns an object: last_hidden_state of shape (N, T, 768) from the encoder, logits from a classifier, and, when labels are in the batch, the cross-entropy loss computed for you. The toolkit's loop needs one adaptation, a batch that is a dict rather than a tuple, which is what fit_lm is.

model = AutoModelForSequenceClassification.from_pretrained("distilbert-base-uncased", num_labels=5)
count_parameters(model)                              66,957,317   of which 3,845 are the new head
out = model(**batch)                                 # batch: input_ids, attention_mask, labels
out.logits.shape, out.loss                           (torch.Size([32, 5]), tensor(1.63, grad_fn=<NllLossBackward0>))

Fine-tuning gently

Three habits protect a pretrained model while it learns your task. A learning rate around 2e-5 with AdamW: fifty times smaller than the 1e-3 that trained your own models, because these weights are already good and one bold step can wreck them. Gradient clipping, which rescales the gradients when their combined norm exceeds a limit, usually 1.0, so a single odd batch cannot produce a giant step. And gradient accumulation, which lets several small batches add their gradients before one optimizer step, so a model whose activations fill the GPU at batch size 8 still trains with the stability of batch size 32. Lesson 2 showed gradients accumulate when nothing zeroes them; here that becomes a feature.

def clip_and_step(model, optimizer, max_grad_norm):
    norm = torch.nn.utils.clip_grad_norm_(model.parameters(), max_grad_norm)   # rescale, return the norm found
    optimizer.step()
    optimizer.zero_grad(set_to_none=True)
    return float(norm)

for i, batch in enumerate(train_loader):
    out = model(**{k: v.to(device) for k, v in batch.items()})
    (out.loss / accumulation_steps).backward()       # gradients add up; the division keeps the scale of a mean
    if (i + 1) % accumulation_steps == 0:
        clip_and_step(model, optimizer, 1.0)

history = fit_lm(tiny, train_loader, val_loader, epochs=3, lr=1e-3, accumulation_steps=2)
history["steps"], history["val_acc"]                 (30, [0.481, 0.575, 1.0])   20 batches per epoch, one step per two batches

Sentence embeddings and search by meaning

The encoder's last_hidden_state is one vector per token. Mean-pool it over the real tokens, Lesson 11's masked mean, and you have one vector per sentence; normalise it to unit length and the dot product of two such vectors is the cosine of the angle between them: 1 for identical meaning, near 0 for unrelated. Embed every menu item once, store the matrix, and a query becomes one matrix-vector product. Encoders trained specifically for this, such as the MiniLM sentence-transformers, give much better neighbours than a plain DistilBERT, and the notebook uses one.

embeddings = embed_texts(encoder, tok, menu)         torch.Size([5, 32]) for the toy encoder; (5, 384) for MiniLM
embeddings.norm(dim=1)                               tensor([1., 1., 1., 1., 1.])
search("spicy chicken ramen with egg", menu, embeddings, encoder, tok, k=3)
[('spicy chicken ramen with soft egg', 0.944), ('green curry with jasmine rice', 0.661), ('crispy fish tacos', 0.497)]   toy weights: shared pieces win

Common errors

TypeError: forward() got an unexpected keyword argument 'labels'
You passed a classification batch to the bare encoder (AutoModel). The encoder has no head and computes no loss; use AutoModelForSequenceClassification, or drop labels from the batch.
IndexError: index out of range in self (from the embedding layer)
Ids from one tokenizer fed to a model trained with another. Tokenizer and model must come from the same checkpoint.
torch.OutOfMemoryError: CUDA out of memory
Halve the loader's batch size and double accumulation_steps; the effective batch and the result stay the same. Also lower max_length: attention memory grows with the square of the sequence length.
Loss climbs and accuracy falls to chance within the first epoch
Learning rate too high for pretrained weights. 2e-5, with warmup if the run is long.
Search returns the same three dishes for every query
The embeddings were not normalised, so the dot product favours whichever vectors are longest. F.normalize(dim=-1) before storing them.
ValueError: Asking to pad but the tokenizer does not have a padding token
Some tokenizers ship without one. Set tok.pad_token = tok.eos_token (or tok.add_special_tokens({"pad_token": "[PAD]"}) and resize the model's embeddings).
