Where we are

Lesson 1's model knows one thing about a delivery: how far it is. Forkcast knows more: how many items are in the bag, whether it is raining, whether the order landed in the dinner rush. This lesson grows the model to use all four, and replaces the part of Lesson 1 that would not survive that growth: the hand-derived gradient formulas. With four weights you would need four formulas; with the networks of Lesson 4 you would need thousands. PyTorch derives them all, from the same code you use to make the prediction.

Autograd: PyTorch takes notes while you compute

Mark a tensor with requires_grad=True and PyTorch records every operation that touches it, building a graph from your inputs to your loss. Call loss.backward() and it walks that graph in reverse, applying the slope of each operation in turn, and deposits the result in each marked tensor's .grad. The slope rules it applies are exactly the ones you used in Lesson 1, which is why the numbers come out identical. Run this tiny example forward, then step backward one node at a time.

In code, the whole thing is three lines, and the model line is the one you already had:

w = torch.tensor(1.0, requires_grad=True)     # "please track slopes for me"
b = torch.tensor(2.0, requires_grad=True)

loss = ((w * x + b - y) ** 2).mean()           # forward: ordinary arithmetic, recorded
loss                                           tensor(389.1, grad_fn=<MeanBackward0>)
loss.backward()                                # backward: slopes flow to w.grad and b.grad
w.grad, b.grad                                 (tensor(-221.6), tensor(-36.7))   same as Lesson 1

Two details matter. .grad is None until the first backward(). And backward() needs a single number to start from: if you call it on the vector of errors instead of their mean, you get an error saying the gradient can only be created for scalar outputs.

Gradients add up until you zero them

Call backward() twice and .grad holds the sum of both slopes, not the latest one. This is deliberate: it lets large batches be split into pieces, which you will use in Lesson 13. In an ordinary training loop it is a trap. Every step must start from a clean .grad, so every step ends with w.grad.zero_(). Press backward a few times and watch; then look at what the same mistake does to a training run.

Forgetting to zero the gradient does not crash. The loss just stops making sense: it drops, jumps back up, drops again, because each step is pushed by every slope that came before. When you see a loss that bounces instead of settling, this is the first thing to check, before the learning rate.

From one feature to many

With four features, a prediction is four weights times four numbers, summed, plus b. For one order that is a dot product. For a batch of N orders stacked as rows of a (N, d) tensor X, it is N dot products at once, and PyTorch spells that X @ w. The shapes tell the story: (N, d) times (d,) gives (N,): the d is consumed, one prediction per order remains. Click each order to see its weighted sum.

from forkcast.data import make_orders, FEATURES, TRUE_WEIGHTS
X, y = make_orders(400, seed=0)
X.shape, y.shape                               (torch.Size([400, 4]), torch.Size([400]))
FEATURES                                       ['distance_km', 'items', 'rain', 'rush_hour']
X[:3]                                          tensor([[5.21, 3., 0., 0.],
                                                       [7.80, 6., 1., 0.],
                                                       [1.34, 1., 0., 0.]])

w = torch.zeros(4)                             # one weight per feature, shape (4,)
(X @ w).shape                                  torch.Size([400])
torch.allclose(X @ w, (X * w).sum(dim=1))      True   @ is the loop you would have written

That last line is worth running once. Broadcasting (X * w) multiplies each row by the weights, sum(dim=1) collapses the d axis, and the result equals X @ w exactly. The matrix multiply is not new maths; it is a name for the loop, and a very fast implementation of it.

The loop, version 2

Here is Lesson 1's fit with autograd doing the slopes and w grown to a vector. Three lines are new, and they are the three lines every PyTorch training loop has:

w = torch.zeros(4, requires_grad=True)
b = torch.zeros((), requires_grad=True)

for step in range(steps):
    loss = ((X @ w + b - y) ** 2).mean()
    loss.backward()                            # 1. slopes into w.grad and b.grad
    with torch.no_grad():                      # 2. the update is not part of the model
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_()                             # 3. clean slate for the next step
    b.grad.zero_()

torch.no_grad() tells autograd to stop taking notes for the lines inside. Without it, the update itself would be recorded as part of the graph, and PyTorch refuses to modify a tracked leaf in place anyway. When the loop is done, return w.detach(): the same numbers, with the recording history cut off, which is what the rest of the program wants.

Common errors

RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn
Nothing on the path to the loss had requires_grad=True, or you called .detach() too early. Check the two knob tensors.
RuntimeError: grad can be implicitly created only for scalar outputs
You called backward() on a tensor with more than one element, usually the errors instead of the loss. Add the .mean().
RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.
The update w -= lr * w.grad is outside with torch.no_grad():. Indent it.
RuntimeError: Trying to backward through the graph a second time
You called backward() twice on the same loss tensor. The graph is freed after the first call. Recompute the loss before each backward(); a training loop does that naturally.
RuntimeError: mat1 and mat2 shapes cannot be multiplied (400x4 and 400x4)
The inner dimensions must match: (N, d) @ (d,). You multiplied X by something shaped like X, or forgot to transpose.
w.grad is None after backward()
The w you are looking at is not the one in the graph. w = w - lr * w.grad (without no_grad and without -=) creates a new, non-leaf tensor each step; gradients go to leaves only. Use the in-place update inside no_grad.
RuntimeError: Can't call numpy() on Tensor that requires grad. Use tensor.detach().numpy() instead.
Plotting a tensor that still carries autograd history. Do what the message says.
