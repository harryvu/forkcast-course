Where we are

Lesson 9 left you with a dish classifier and an accuracy number. In Forkcast that number decides things: whether a restaurant's photo is flagged as mislabelled, whether a search by picture returns the right dishes. Before a model with 80% accuracy touches real users, you need to know what the other 20% looks like, whether it is spread evenly or piled onto two classes, whether the model is reading the dish or the plate, and whether its 95% is really 95%. None of these are in the loss curve. This lesson is the toolkit for finding them.

Look at the mistakes

Start with the most informative errors: the ones the model was sure about. Sort every wrong prediction by the softmax probability of the predicted class and look at the top of the list. A confident mistake is one of two things, a systematic blind spot in the model or a mislabelled image in the data, and a gallery of the top sixteen usually tells you which within a minute. Low-confidence mistakes are the model being honestly unsure; they are expected and less interesting.

def misclassified(logits, y, k=16):
    probs = torch.softmax(logits, dim=1)
    confidence, predicted = probs.max(dim=1)
    wrong = (predicted != y).nonzero().flatten()
    order = wrong[confidence[wrong].argsort(descending=True)][:k]
    return [(int(i), int(y[i]), int(predicted[i]), float(confidence[i])) for i in order]

picks = misclassified(logits, y, k=16)
plt.imshow(gallery(images, picks).permute(1, 2, 0))   # the sixteen pictures worth your attention

Class balance

Count the training labels. If pizza has 400 photos and laksa has 40, a model that never predicts laksa loses almost nothing on the training loss, and its 90% accuracy is mostly the common classes. The per-class accuracies from Lesson 9 will show it; the fix is to make rare mistakes expensive. CrossEntropyLoss(weight=w) multiplies each image's loss by its class's weight, and inverse-frequency weights, total divided by classes times count, give every class the same total say regardless of size.

counts = class_counts(train_labels, n_classes)       tensor([400, 350, 300,  80,  60,  40])
weights = class_weights(counts)                       tensor([0.5125, 0.5857, 0.6833, 2.5625, 3.4167, 5.1250])   count × weight = 205 for every class
loss_fn = nn.CrossEntropyLoss(weight=weights.to(device))

Hooks: reading a layer without editing the model

A forward hook is a function you attach to a layer; PyTorch calls it every time the layer runs, with the module, its inputs and its output. It is how you look at intermediate tensors in a model you did not write, including every pretrained backbone. Two rules: the output is a tensor still in the graph, so .detach() it if you only want to look, and remove the hook with the handle you were given, or it fires on every forward pass for the rest of the session.

def record_activation(model, layer, x):
    captured = {}
    def hook(module, inputs, output):
        captured["out"] = output.detach()
    handle = layer.register_forward_hook(hook)
    try:
        model(x)
    finally:
        handle.remove()
    return captured["out"]

record_activation(model, model.features[6], images).shape   torch.Size([8, 32, 16, 16])

Grad-CAM: where did it look?

Take the activations of a late convolutional layer, a stack of 32 grids of 16×16. For the class you care about, ask autograd how its score changes with each activation: one gradient per grid cell. Average those over the grid, and each channel gets a single weight: how much that channel's pattern supports the class. Weight the grids, add them up, keep the positive part, and you have a 16×16 heatmap over the image of the evidence the model used. On the synthetic shapes the heat sits on the shape: inside it averages 0.2 to 0.5, the background under 0.15. On dish photos it tells you whether the model found the food or the fork.

class GradCAM:
    def __init__(self, model, layer):
        self.model, self.activations = model, None
        self.handle = layer.register_forward_hook(self._capture)
    def _capture(self, module, inputs, output):
        self.activations = output                        # left in the graph, on purpose
    def __call__(self, x, class_idx=None):
        self.model.eval()
        with torch.enable_grad():
            x = x.clone().requires_grad_(True)           # works even when every parameter is frozen
            logits = self.model(x)
            if class_idx is None:
                class_idx = logits.argmax(dim=1)
            score = logits.gather(1, class_idx.view(-1, 1)).sum()
            grads, = torch.autograd.grad(score, self.activations)       # (N, 32, 16, 16)
        weights = grads.mean(dim=(2, 3), keepdim=True)                  # (N, 32, 1, 1)
        cam = torch.relu((weights * self.activations).sum(dim=1))       # (N, 16, 16)
        return (cam / cam.flatten(1).max(dim=1).values.clamp_min(1e-8)[:, None, None]).detach()
    def remove(self):
        self.handle.remove()

Ask for a different class and the map moves: cam(x, class_idx=...) shows what would have supported "circle" in a picture of a cross. On Lesson 9's ResNet, hook model.layer4; its grid is 7×7 for a 224×224 input, and upsampling it over the photo gives the familiar red blob.

Calibration: does 90% mean 90%?

A classifier's softmax looks like a probability. Whether it behaves like one is a separate, measurable question: among all predictions made with 90% confidence, were 90% right? Bin predictions by confidence, compute accuracy per bin, and plot it against the diagonal. The weighted average gap is the expected calibration error. Neural networks trained with cross-entropy are usually overconfident, and overconfidence is what hurts in a product: a 95% that is really 70% overrules the human who was right.

probs = torch.softmax(logits, dim=1)
expected_calibration_error(probs, y)                 0.077    Lesson 7's SmallCNN on the shapes: accuracy 0.925, mean confidence 0.86
conf, acc, count = reliability_bins(probs, y)
bin confidence  0.35  0.46  0.55  0.66  0.75  0.85  0.97
bin accuracy    0.50  0.45  0.46  0.92  0.92  0.96  1.00
count              2    11    26    24    51    68   218

Here the model is slightly underconfident in the middle bins and well calibrated at the top, which is fine. If the top bin had read 0.97 confidence and 0.80 accuracy, you would reach for the fixes: label smoothing during training, or temperature scaling, a single number fitted on the validation set that divides the logits before the softmax and does nothing to accuracy.

Common errors

RuntimeError: One of the differentiated Tensors appears to not have been used in the graph
The hooked layer did not run in this forward pass (wrong layer, or a model with branches), or you detached the activations in the hook. Grad-CAM needs them attached.
RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn
Every parameter is frozen and the input does not require grad either, so nothing is in the graph. x.clone().requires_grad_(True) before the forward pass.
The heatmap is all zeros for some images
Normal for an untrained or unsure model: the ReLU removes negative evidence and nothing positive was left. On a trained model, check you asked for a class the model considers plausible.
Memory climbs with every forward pass
A hook that appends to a list and was never removed. Hooks outlive the cell that created them; remove them in a finally.
ECE is exactly 0 but the model is clearly bad
You passed logits instead of softmax probabilities, so every "confidence" landed in the same overflow bin, or n_bins is 1. Softmax first; ten bins.
RuntimeError: weight tensor should be defined either for all 4 classes or no classes
The weight vector's length does not match the number of logits. class_weights(class_counts(labels, n_classes)) with the right n_classes.

Stretch

Implement temperature scaling: a single scalar T, fitted on the validation logits by minimising cross-entropy of logits / T, then applied before the softmax. Accuracy does not change; ECE should drop. Then run Grad-CAM for the top-2 classes of each misclassified dish photo side by side; when the two maps light up different parts of the plate, you have found the model's actual dilemma.
