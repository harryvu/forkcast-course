Where we are

Forkcast restaurants upload photos of their dishes, and the app needs to know what is in them: to check a listing, to search by picture, eventually to recommend. That is image classification, and it is where neural networks first became unavoidable. The data pipeline from Lesson 6 carries over unchanged; what changes is the shape of an item and the layers that read it. To keep the tests offline and fast, the repository draws its own pictures: coloured circles, squares, triangles and crosses. The notebook trains the same network on real dish photos.

Images are tensors with four dimensions

A colour image is three grids of numbers, one per channel, red, green and blue, each H rows by W columns. PyTorch stores a batch as (N, C, H, W): channels before height and width, which trips up everyone coming from image libraries that put channels last; Lesson 0's permute is the fix when you meet one. Pixel values arrive as integers 0 to 255 and are scaled to 0 to 1, then normalized per channel with the mean and standard deviation of the training set, the Normalizer idea with one mean per channel instead of one per column.

from forkcast import vision
images, labels = vision.make_shapes(8, seed=0)
images.shape, images.dtype                           (torch.Size([8, 3, 32, 32]), torch.float32)

images.mean(dim=(0, 2, 3))                           tensor([0.087, 0.090, 0.095])   one mean per channel: mostly dark background

Convolution: a few weights, slid everywhere

A fully connected layer on a 32×32 colour image would need 3072 weights per output, and it would have to learn separately that an edge in the top-left corner and the same edge in the bottom-right are the same thing. A convolution uses a small kernel of weights, 3×3 here, and slides it across the image, computing a weighted sum at every position. The same nine weights everywhere: far fewer parameters, and a pattern is detected wherever it appears. Each kernel produces one output grid, a feature map; a layer with 16 output channels has 16 kernels. Slide one.

The output size follows from how many positions the kernel can occupy: floor((size + 2·padding − kernel) / stride) + 1. With a 3×3 kernel, padding=1 keeps the size and stride=2 halves it. You will compute this constantly, so it is the first exercise. In nn.Conv2d(in_channels, out_channels, kernel_size) the weight has shape (out, in, k, k): every kernel looks at all input channels at once, so a kernel in the second layer sees all 16 feature maps of the first.

Pooling, BatchNorm, and stacking blocks

Between convolutions, MaxPool2d(2) keeps the largest value in each 2×2 patch, halving height and width. It has no weights; it makes the network indifferent to a shift of a pixel and lets the next layer's 3×3 kernels cover a wider region of the original image. Stack conv, pool, conv, pool, and the receptive field grows: the first layer sees edges, the second sees corners and strokes made of edges, a third would see parts of shapes.

BatchNorm2d sits after each convolution and normalizes every channel's activations across the batch, then rescales them with two learned numbers per channel. It is the Normalizer idea applied inside the network, and it lets you train deeper networks with larger learning rates. Like dropout, it behaves differently in training (batch statistics) and evaluation (running averages), so the model.train()/model.eval() calls in the toolkit are now doing two jobs.

The network, shape by shape

class SmallCNN(nn.Module):
    def __init__(self, n_classes=4, size=32):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, kernel_size=3, padding=1), nn.BatchNorm2d(16), nn.ReLU(), nn.MaxPool2d(2),   # (N, 16, 16, 16)
            nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),  # (N, 32, 8, 8)
        )
        self.head = nn.Sequential(
            nn.Flatten(),                                        # (N, 32 * 8 * 8) = (N, 2048)
            nn.Linear(32 * (size // 4) ** 2, 64), nn.ReLU(),
            nn.Linear(64, n_classes),                            # (N, 4) logits
        )
    def forward(self, x):
        return self.head(self.features(x))

model = SmallCNN()
model.features(images).shape                         torch.Size([8, 32, 8, 8])
model(images).shape                                  torch.Size([8, 4])
count_parameters(model)                              136580   of which 131136 are in the first Linear

Read the parameter count: the convolutions hold about 5000 weights between them, the 2048-to-64 linear layer holds 131,136. That imbalance is why real networks keep pooling until the map is tiny, or average it down to one number per channel, before the classifier. It is also why Flatten must come after the last pool and nowhere else.

Classification: logits, probabilities, loss

Until now the model produced one number, minutes, and the loss was a squared distance. A classifier produces one number per class, the logits, which can be any real values. softmax turns them into probabilities that sum to one; the predicted class is the argmax. The loss is cross-entropy: minus the log of the probability the model gave the true class. Right and confident costs almost nothing; wrong and confident costs a lot, with no upper limit. nn.CrossEntropyLoss takes the raw logits and integer labels and does the softmax inside, more accurately than you would by hand, which is why the model's last layer has no activation.

logits = model(images[:1])
logits                                               tensor([[ 2.33,  0.39, -2.56, -2.25]])
torch.softmax(logits, dim=1)                         tensor([[0.861, 0.123, 0.006, 0.009]])   86% circle, and it is a circle
nn.CrossEntropyLoss()(logits, labels[:1])            tensor(0.150)                           -log(0.861)
vision.accuracy(model(images), labels)               1.0

Accuracy is the fraction of correct argmax decisions. It is what you report; it is not what you train on, because it is flat almost everywhere: nudging a weight rarely flips a decision, so it has no useful gradient. Cross-entropy is the smooth stand-in whose gradient points toward higher accuracy. Keep both in view: loss for the optimizer, accuracy for you.

Common errors

RuntimeError: Given groups=1, weight of size [16, 3, 3, 3], expected input[8, 32, 32, 3] to have 3 channels, but got 32 channels instead
Channels-last input. PyTorch wants (N, C, H, W); use permute(0, 3, 1, 2) on the way in.
RuntimeError: mat1 and mat2 shapes cannot be multiplied (8x8192 and 2048x64)
The head's first Linear was sized for the wrong image size or the wrong number of pools. Recompute 32 × (size // 4)², or print features(x).shape and build the Linear from it.
RuntimeError: Expected floating point type for target with class probabilities, got Long
You passed one-hot or float targets where CrossEntropyLoss wanted class indices, or indices where it wanted probabilities. Give it integer labels of shape (N,).
IndexError: Target 4 is out of bounds
A label equal to n_classes. Labels run from 0 to n_classes − 1; the model's last Linear needs as many outputs as there are classes.
Accuracy stuck at 0.25 (chance) while the loss falls
Usually a shuffled-labels bug: images and labels were permuted separately, or shuffle=True was applied to two loaders built from separate tensors. Keep them in one TensorDataset.
Validation accuracy swings wildly between epochs
BatchNorm in train mode during evaluation, or a tiny validation set. Make sure evaluate_loader calls model.eval(); the toolkit's does.
