Linear regression by hand

Where we are

Forkcast needs to tell customers how long a delivery will take. This lesson builds the first, deliberately simple version: predict minutes from distance alone. The data is synthetic, generated by forkcast.data.make_deliveries from a rule we know: minutes = 8 + 3.5 × km + noise. That is the point of starting synthetic. When your model finishes learning, you can compare what it found to the truth, which real data never lets you do.

Everything you build today, you will replace with PyTorch's own parts over the next two lessons: the hand-written gradient with autograd in Lesson 2, the update step with torch.optim in Lesson 3. Knowing what those parts do inside is what lets you debug them later.

A model is a function with knobs

A model takes an input and returns a prediction, using some numbers it can adjust. Ours has two: w, the minutes added per kilometre, and b, the minutes a delivery takes before the rider moves. In PyTorch they are 0-dimensional tensors, shape (), and the prediction for a batch of distances (N,) is one line of broadcasting:

pred = w * x + b          # () * (N,) + ()  ->  (N,)

Before any maths, do it by feel. Move the two knobs until the line goes through the cloud of deliveries.

Loss: one number for how wrong

You just judged the fit by eye. A program needs a number. For each delivery, the error is prediction − actual, positive when the model is too slow and negative when too fast. Squaring removes the sign and punishes big misses more than small ones; averaging gives one number for the whole batch. That number is the mean squared error, and making it small is the whole job.

errors = pred - y                       # (N,)  one error per delivery
loss = (errors ** 2).mean()              # ()    a single number
loss.item()                              740.5   as a plain Python float

Loss is a function of the knobs: change w and the loss changes. With b held fixed, that function is a curve, and it has a lowest point. Finding it is the next idea.

Gradient: which way is down

Stand on the loss curve at your current w. The ground has a slope. If it slopes up to the right, decrease w; if it slopes down to the right, increase it. The slope's steepness tells you how confident to be: steep means far from the bottom, flat means close. That slope is the gradient, and the rule move a little against the slope is gradient descent. How little is the learning rate.

Three things to notice. Steps shrink by themselves near the bottom, because the slope does. The learning rate is a trade: too small and you wait, too large and each step overshoots the valley and climbs the far wall, where the slope is steeper, so the next step is larger still. And nothing here knows what a delivery is: the same rule works for the millions of knobs in Lesson 9.

The two formulas

You need the slope of the loss with respect to each knob. Here is all the calculus this course asks of you. For one delivery with error e = w·x + b − y, the squared error e² has slope 2e with respect to e. When w grows by 1, e grows by x; when b grows by 1, e grows by 1. Multiply, then average over the batch:

e  = w * x + b - y                       # (N,)
dw = 2 * (e * x).mean()                  # ()  slope of the loss along w
db = 2 * e.mean()                        # ()  slope of the loss along b

w = w - lr * dw                          # one step downhill
b = b - lr * db

If the second formula feels like a special case of the first with x = 1, that is because it is: b is a weight on a feature that is always 1. Lesson 2 uses that trick, and then makes PyTorch derive both lines for you.

Questions

Work these on paper first.

2. Predictions [11, 14], actual minutes [10, 15]. What is the mean squared error?

3. Same errors [1, −1], distances [1, 2]. What is dL/dw?

4. w = 2, slope dL/dw = 5, learning rate 0.1. What is w after one step?

5. w = 1, slope dL/dw = −4, learning rate 0.5. What is w after one step?

  5. Write gradient_step and fit

    gradient_step returns the new w and b. fit starts from w0, b0, and for each of steps iterations records the current loss with .item() and then takes one step. Return the final knobs and the list of losses.

  6. Fit, and compare with the truth

    w, b, losses = linear.fit(x, y, lr=0.01, steps=3000)
print(w.item(), b.item())                 3.54  7.63   (data was made with 3.5 and 8.0)
print(losses[0], losses[-1])              740.5  4.46

plt.plot(losses); plt.yscale("log"); plt.xlabel("step"); plt.ylabel("loss");

    Expected: a steep drop in the first hundred steps, then a long slow slide. The final loss is near 4, which is the noise² the data was made with: the model has learned everything there was to learn.

  7. Break it on purpose

    _, _, bad = linear.fit(x, y, lr=0.1, steps=60)
bad[:5], bad[-1]                           ([740.5, 23240.8, 744136.5, 23840218.0, ...], nan)

    Ten times the learning rate, and the loss grows thirty-fold every step until it overflows to nan. This is what divergence looks like in a log: the first thing to check when a model's loss becomes nan is the learning rate.

Common errors

loss.shape is torch.Size([200, 200]) and the loss is huge
One of pred or y has shape (200, 1) and the other (200,). Broadcasting happily makes a 200×200 table of every prediction against every target. Check the shapes with the broadcasting rule from Lesson 0, and reshape(-1) or squeeze the odd one out. This bug produces no error message, which is why you always check shapes.
RuntimeError: a Tensor with 200 elements cannot be converted to Scalar
.item() only works on a single number. You called it on the errors instead of the loss, or forgot the .mean().
The loss goes down for a few steps, then up, then nan
The learning rate is too large for this data. Divide it by 10. In Lesson 3 you will see the real fix: normalising the inputs so one learning rate works for everything.
w and b never move, or move incredibly slowly
Either the learning rate is tiny, or fit is not using the values returned by gradient_step: gradient_step(x, y, w, b, lr) on its own line does nothing. Write w, b = gradient_step(...).
TypeError: unsupported operand type(s) for *: 'float' and 'list'
Something is a Python list instead of a tensor. Everything that enters predict must be a tensor; wrap with torch.tensor(...).

Stretch

Two experiments, no new tests. First, start from w0 = 10, b0 = -20 and plot the path of (w, b) over the steps; it curves because the loss surface is a stretched bowl, not a round one. Second, standardise x with the normalize_columns idea from Lesson 0 (subtract the mean, divide by the std), fit again with lr = 0.1, and count how many steps it takes to get within 0.1 of the best loss. That speed-up is the reason Lesson 3 normalises everything.
