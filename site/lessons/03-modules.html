Definition of done

Lesson 3 is done. Your training loop is now the real one; the rest of the course changes what goes into it.

Where we are

You have a working four-feature model and a loop that trains it. Two things about it would not survive contact with the rest of the course. The knobs are loose tensors you pass around by hand, which gets unmanageable the moment there are more than two. And the learning rate has been a nuisance since Lesson 1: 0.01 works, 0.1 explodes, and in Lesson 2 you had to drop to 0.005 for no better reason than that distances are bigger numbers than rain flags. This lesson fixes both, and leaves behind three functions in forkcast/train.py that every later lesson calls.

The model becomes an object

An nn.Module is a class that owns parameters and knows how to compute with them. You write two methods: __init__ creates the layers, forward says how input flows through them. Everything else, collecting the parameters for the optimizer, saving and loading, moving to a GPU, comes for free. The one layer you need today is nn.Linear, which is Lesson 2's X @ w + b as an object. Look at what it holds, and watch the shapes when the output grows.

from torch import nn

class LinearRegressor(nn.Module):
    def __init__(self, n_features):
        super().__init__()                        # always first: this is what registers the parameters
        self.linear = nn.Linear(n_features, 1)    # weight (1, d), bias (1,), random start

    def forward(self, X):                         # (N, d) -> (N,)
        return self.linear(X).squeeze(-1)         # nn.Linear gives (N, 1); y is (N,)

model = LinearRegressor(4)
model(X).shape                                    torch.Size([400])    calling the model runs forward()
model.linear.weight                               tensor([[-0.004, 0.268, -0.412, -0.368]], requires_grad=True)
sum(p.numel() for p in model.parameters())        5

That squeeze(-1) is the Lesson 1 silent bug, pre-empted. nn.Linear always returns a trailing dimension of size out_features, here 1. Compare a (400, 1) prediction with a (400,) target and broadcasting quietly builds a 400 by 400 table; nn.MSELoss at least warns you about it now. Squeeze, and the shapes agree.

The optimizer owns the update

In Lesson 2 the update was two lines inside no_grad, one per knob. An optimizer is handed model.parameters() once and applies the update rule to all of them on step(), and zeroes all their gradients on zero_grad(). Your loop shrinks to five lines, and the five lines are the same for a 5-parameter model and a 50-million-parameter one.

torch.optim.SGD is exactly Lesson 2's rule, w -= lr * w.grad. torch.optim.Adam keeps a running memory of each parameter's past gradients and scales its own step size per parameter; it is far more forgiving of a badly chosen learning rate and is the default choice for most of this course. Swapping one for the other is one word.

Why one learning rate kept failing

Distances run from 0.5 to 10, item counts from 1 to 6, and the rain flag is 0 or 1. The weight on distance feels every step a hundred times more strongly than the weight on rain, because the gradient for each weight is scaled by its feature's size. The loss is still a bowl, but a long narrow one: a step small enough to be safe along the steep direction crawls along the shallow one. Standardize every feature to mean 0 and standard deviation 1 and the bowl becomes round. Run both with the same learning rate.

class Normalizer:
    def fit(self, X):                               # learn the statistics from the training data
        self.mean = X.mean(dim=0)                   # (d,)
        self.std = X.std(dim=0, correction=0).clamp_min(1e-6)
        return self
    def transform(self, X):                         # apply the stored statistics to any data
        return (X - self.mean) / self.std           # Lesson 0's normalize_columns, made reusable

norm = Normalizer().fit(X)
norm.mean, norm.std                                 tensor([5.21, 3.52, 0.31, 0.25]), tensor([2.74, 1.71, 0.46, 0.43])
Xn = norm.transform(X)

Two rules. The statistics come from the training data and are then applied to validation and test data, never recomputed on them; Lesson 5 explains the leak that happens otherwise. And a model trained on normalized inputs expects normalized inputs forever: the Normalizer is part of the model, and ships with it in Lesson 15.

The toolkit

Three functions go into forkcast/train.py and stay there. train_one_epoch is one pass over the data: the five lines above, plus model.train() at the top. evaluate measures the loss without learning, under @torch.no_grad(), with model.eval(). Right now the two mode switches do nothing; from Lesson 5 dropout behaves differently in each, and forgetting them is a classic error that this habit prevents. fit builds the optimizer and loops. And two helpers save and load a state_dict, the dictionary of every parameter tensor by name.

model.state_dict().keys()                          odict_keys(['linear.weight', 'linear.bias'])
torch.save(model.state_dict(), "linear.pt")        # numbers only, no code
fresh = LinearRegressor(4)
fresh.load_state_dict(torch.load("linear.pt", weights_only=True))
torch.equal(fresh(X), model(X))                    True

  3. Write LinearRegressor in forkcast/model.py

    Two lines in __init__ (the super().__init__() call and the layer), one in forward. Check: model(X).shape is (400,), and model(X) equals X @ model.linear.weight[0] + model.linear.bias[0].

  4. Write Normalizer in forkcast/preprocess.py

    fit stores the column mean and std (with correction=0 and clamp_min(1e-6)) and returns self; transform uses them. Check that norm.transform(X).mean(dim=0) is four zeros and the std is four ones, and that norm.mean matches the numbers above.

  5. Write train_one_epoch, evaluate and fit in forkcast/train.py

    The docstrings give the order of the lines. train_one_epoch returns loss.item() of the loss it just stepped on. fit defaults the loss to nn.MSELoss(), builds optimizer_cls(model.parameters(), lr=lr), and returns one float per epoch.

  6. Fit on normalized features

    from forkcast.model import LinearRegressor
from forkcast.preprocess import Normalizer
from forkcast import train

norm = Normalizer().fit(X)
Xn = norm.transform(X)
torch.manual_seed(0)
model = LinearRegressor(4)
losses = train.fit(model, Xn, y, epochs=300, lr=0.1)
losses[0], losses[-1]                              (1285.1, 3.87)   below 5 by epoch 16

model.linear.weight[0], model.linear.bias          tensor([9.33, 2.74, 1.81, 2.57]), tensor([34.05])

    Those weights look nothing like TRUE_WEIGHTS, and they are right: they are minutes per standard deviation of each feature, and the bias is the average delivery time. Undo the scaling to compare with the generator:

    w, b = model.linear.weight[0].detach(), model.linear.bias[0].detach()
w / norm.std                                       tensor([3.40, 1.60, 3.93, 5.99])   truth [3.5, 1.5, 4.0, 6.0]
b - (w * norm.mean / norm.std).sum()               tensor(8.04)                       truth 8.0

    Expected: a learning rate of 0.1, twenty times what Lesson 2 needed, converging in a few dozen epochs instead of thousands.

  7. Break it on purpose: the same learning rate on raw features

    torch.manual_seed(0)
raw = train.fit(LinearRegressor(4), X, y, epochs=60, lr=0.1)
raw[:4], raw[-1]                                   ([1234.0, 85257.7, 6026245.0, 426079424.0], nan)

torch.manual_seed(0)

adam[-1]                                           5.47   Adam copes with raw features; normalization still wins

    Same model, same data, same learning rate, different scale: SGD explodes in four steps. Adam's per-parameter step sizes rescue it, which is a good reason to prefer Adam, but not a reason to skip normalization: the normalized SGD run reached 3.87.

Common errors

AttributeError: cannot assign module before Module.__init__() call
self.linear = ... ran before super().__init__(). The parent constructor sets up the registry that stores layers; call it first.
UserWarning: Using a target size (torch.Size([400])) that is different to the input size (torch.Size([400, 1]))
The prediction still has its trailing 1. Add .squeeze(-1) in forward. This warning is the loud version of Lesson 1's silent 200×200 bug; treat it as an error.
RuntimeError: mat1 and mat2 shapes cannot be multiplied (400x1 and 4x1)
nn.Linear(4, 1) expects inputs with 4 columns. You passed a single feature or a transposed tensor.
TypeError: forward() takes 1 positional argument but 2 were given
def forward(X) is missing self.
RuntimeError: Error(s) in loading state_dict for LinearRegressor: size mismatch for linear.weight
The model you are loading into was built with a different n_features than the one that was saved. The file holds numbers only; the shapes must already agree.
The loss is nan after a few epochs
Raw features with a learning rate meant for normalized ones. Normalize, or lower the rate, or switch to Adam. If it still happens, check that zero_grad() is in the loop.
Predictions on new data are wildly wrong, training loss was fine
The new data was not passed through the same Normalizer, or a new one was fitted on it. The model expects inputs scaled with the training statistics.
