Definition of done

Lesson 4 is done. You have trained a neural network, and you know which three lines make it one.

Where we are

The deliveries so far were made by a rule that is a straight line, so a straight line could learn it perfectly. Real deliveries are not like that. Rain does not add a fixed four minutes; it slows every kilometre. Past seven kilometres, Forkcast riders have to leave the main road for the bike-lane detour and the minutes climb faster. This lesson switches the generator to those rules with make_orders(nonlinear=True), watches the linear model fail, and builds the first model that can bend.

Where a line fails, and how to see it

Fit Lesson 3's LinearRegressor to the new deliveries and the loss stops at about 15, far above the noise floor of 4. The loss number says the model is missing something; a residual plot says what. Subtract actual minutes from predicted minutes and plot the difference against distance. A model that has captured everything leaves a shapeless band around zero. This one does not.

This plot is the most useful diagnostic you will own. Any time a loss plateaus above where you think it should, plot the residuals against each feature. A trend means there is a pattern left to learn and the model cannot express it.

Bending the line

A hidden layer is an nn.Linear whose outputs are not the answer. With one input and H hidden units it computes H different lines of the input. Then an activation changes each one; the usual choice is ReLU, max(0, z), which clips negatives to zero and turns each line into a ramp: flat, then rising (or falling) from the point where its line crosses zero, its kink. The output layer is one more nn.Linear that adds the ramps up with its own weights. A sum of ramps is a bent line, with up to H bends, placed wherever the data needs them. Train one.

Now set the activation to none and train again. The fit is a straight line and stays one, with 1 unit or 16. That is the whole reason activations exist, and it is the next section.

Stacking layers

Two linear layers in a row compute W2 (W1 x + b1) + b2, which is (W2 W1) x + (W2 b1 + b2): a single matrix times x plus a single bias. However many linear layers you stack, the result is one linear layer with a lot of redundant parameters. The activation between them is what stops the collapse, because max(0, ·) is not a matrix. So the recipe for a network is Linear, activation, Linear, activation, Linear, with no activation after the last layer, since minutes can be any number and ReLU would forbid negatives.

class MLP(nn.Module):
    def __init__(self, n_features, hidden=(32, 32), activation=nn.ReLU):
        super().__init__()
        layers, width = [], n_features
        for h in hidden:
            layers.append(nn.Linear(width, h))      # (N, width) -> (N, h)
            layers.append(activation())             # the bend
            width = h
        layers.append(nn.Linear(width, 1))          # no activation after the output
        self.net = nn.Sequential(*layers)

    def forward(self, X):
        return self.net(X).squeeze(-1)

MLP(4, (32, 32)).net
Sequential(
  (0): Linear(in_features=4, out_features=32, bias=True)
  (1): ReLU()
  (2): Linear(in_features=32, out_features=32, bias=True)
  (3): ReLU()
  (4): Linear(in_features=32, out_features=1, bias=True)
)

nn.Sequential runs its children in order and is itself a module, so state_dict names the parameters net.0.weight, net.2.weight, net.4.weight: the ReLUs at positions 1 and 3 have nothing to save. The shapes chain: (N, 4) becomes (N, 32), stays (N, 32), becomes (N, 1), and the squeeze makes it (N,). Nothing else in the training loop changes: train.fit from Lesson 3 takes this model as it took the last one.

Capacity

Parameters are what a network has to bend with. Count them: a Linear(in, out) has in × out + out, and the total for 4 → 32 → 32 → 1 is 160 + 1056 + 33 = 1249, against the 5 of the straight line. Here is what the same recipe learns on the new deliveries at different widths, with Adam at lr = 0.01 for 300 epochs:

LinearRegressor         5 parameters    loss 15.43
MLP(4, (8,))           49 parameters    loss 24.44   too small to bend enough, and slow to train
MLP(4, (32,))         193 parameters    loss  7.16
MLP(4, (32, 32))     1249 parameters    loss  5.44
MLP(4, (64, 64))     4545 parameters    loss  4.79   the noise floor is about 4

More capacity, lower loss, all the way down to the noise. That looks like a rule you can follow forever. It is not: these numbers are the loss on the data the model trained on, and Lesson 5 shows what happens to the loss on deliveries it has never seen when you keep turning capacity up.

Build it

forkcast/model.py grows count_parameters and MLP. forkcast/data.py already has the nonlinear=True switch.

  1. Open the Lesson 4 notebook and run the setup cell

    Open lesson04.ipynb in Colab

  2. Load the new deliveries and fit the old model

    import torch
from forkcast.data import make_orders, FEATURES
from forkcast.model import LinearRegressor
from forkcast.preprocess import Normalizer
from forkcast import train

X, y = make_orders(2000, seed=0, nonlinear=True)
norm = Normalizer().fit(X)
Xn = norm.transform(X)

torch.manual_seed(0)
lin = LinearRegressor(4)
losses = train.fit(lin, Xn, y, epochs=300, lr=0.1)
losses[-1]                                         15.43   stuck well above the noise floor of 4

  3. Plot the residuals

    import matplotlib.pyplot as plt
with torch.no_grad():
    residual = lin(Xn) - y
plt.scatter(X[:, 0], residual, s=6, c=X[:, 2])   # colour = rain
plt.axhline(0, color="k", ls="--"); plt.xlabel("km"); plt.ylabel("prediction − actual");

    Expected: the cloud bends downward past 7 km (the model under-predicts far deliveries), and the rainy points drift away from the dry ones as distance grows.

  4. Write count_parameters and MLP

    In the %%writefile forkcast/model.py cell, below LinearRegressor. Build a Python list of layers in a loop over hidden, append the output layer, and wrap the list with nn.Sequential(*layers). Check:

    from forkcast.model import MLP, count_parameters
model = MLP(4, (32, 32))
model.net                                          Sequential(... five modules, as above)
model(Xn).shape                                    torch.Size([2000])
count_parameters(model)                            1249

  5. Train it with the toolkit

    torch.manual_seed(0)
model = MLP(4, (32, 32))
losses = train.fit(model, Xn, y, epochs=300, lr=0.01, optimizer_cls=torch.optim.Adam)
losses[0], losses[-1]                              (1751.0, 5.44)
plt.plot(losses); plt.yscale("log");

    Expected: the first loss is huge, because a fresh network predicts near zero and deliveries average 39 minutes; then a long slide down past where the line stopped. Nothing in train.fit changed.

  6. Plot the residuals again

    Same cell as step 3 with model in place of lin. The bend at 7 km is gone and the rainy points sit with the dry ones: a band around zero, no trend. That is what "the model has learned the structure" looks like.

  7. Break it on purpose, twice

    torch.manual_seed(0)
flat = train.fit(MLP(4, (32, 32), activation=nn.Identity), Xn, y, epochs=300, lr=0.01, optimizer_cls=torch.optim.Adam)
flat[-1]                                           15.43   identical to the straight line, with 1249 parameters

torch.manual_seed(0)
sgd = train.fit(MLP(4, (32, 32)), Xn, y, epochs=300, lr=0.1)
sgd[-1]                                            nan     Lesson 3's SGD learning rate is too hot for a network

    The first run is the proof of the stacking argument: no activation, no bend, and the extra 1244 parameters buy exactly nothing. The second is a reminder that the learning rate that suited a 5-parameter line does not suit a network; Adam at 0.01 is the safe default from here.

Common errors

TypeError: 'ReLU' object is not callable (or: activation() missing argument)
activation is a class; call it to make a layer, nn.ReLU(). If you passed an instance (MLP(4, (32,), nn.ReLU())), you now have an object being called like a class.
TypeError: list is not a Module subclass
You assigned the plain Python list to self.net. Wrap it: nn.Sequential(*layers), with the star.
RuntimeError: mat1 and mat2 shapes cannot be multiplied (2000x32 and 4x32)
The loop did not update width after each hidden layer, so the second layer was built as Linear(4, 32) instead of Linear(32, 32).
The loss plateaus near 15, the same as the linear model
No activation between the layers: you forgot to append it, or appended nn.Identity. Print model.net and look for ReLU.
The network predicts only positive values and the loss is stuck
An activation after the output layer. The last Linear must be the last module.
Loss is nan
SGD at Lesson 3's learning rate. Use Adam at 0.01, or SGD at 0.01 or below.
