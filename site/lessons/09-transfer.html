Transfer learning and evaluation

Part 2, Vision. About 2.5 hours. GPU runtime. You'll leave with a dish classifier built on a network that already knows how to see, trained in minutes, and the tools to say exactly where it fails.

Objectives

  2. Freeze it, replace its head, and train only the head, first on cached features in seconds.

Definition of done

Lesson 9 is done. This is how nearly every real vision model is built: start from one that works.

Where we are

Lesson 7's SmallCNN learned to see from two thousand dish photos and did noticeably better than guessing. Forkcast has thousands of restaurants and a hundred kinds of dish, and no amount of patience will get a network trained from scratch on that little data to a useful accuracy. The way out is not more Forkcast data. It is to start from a network that someone else trained on a million photos, keep the parts that know what edges, textures and objects look like, and teach only the last part what our dishes look like. That is transfer learning, and it is how nearly every vision model in production is made.

Borrowed eyes

torchvision.models ships architectures with weights trained on ImageNet, 1.3 million photos of a thousand everyday things. ResNet-18 is the small one: 11.7 million parameters in a stem, four stages of residual blocks, a global average pool and a 512-to-1000 linear head. The early stages respond to edges and textures, which are the same in any photograph; the late stages respond to object parts and whole objects, which are closer to ImageNet's categories. The split between "general" and "specific" is what decides what to freeze.

from torchvision import models
weights = models.ResNet18_Weights.DEFAULT
model = models.resnet18(weights=weights)              # downloads 45 MB once
sum(p.numel() for p in model.parameters())           11689512
model.fc                                             Linear(in_features=512, out_features=1000, bias=True)   ImageNet's thousand classes
weights.transforms()                                 resize 256, centre crop 224, normalize with mean [0.485, 0.456, 0.406], std [0.229, 0.224, 0.225]

The transforms matter as much as the weights: the network learned on images normalized with those exact means and standard deviations, so ours must be too. Use weights.transforms() rather than typing the numbers.

Freeze, replace the head, train

Three moves. requires_grad_(False) on every parameter: autograd stops tracking them, no gradients, no updates, no memory for them. Then replace model.fc with a new nn.Linear(512, n_classes); a new layer requires gradients by default, so it is the only thing that trains. Then the toolkit's fit_v2, unchanged. Since the backbone is frozen, its 512-d output for each image never changes, which allows a trick: run the backbone once over the whole dataset, cache the features, and train the head on them. Seconds instead of minutes, and you can try ten heads.

def build_transfer_model(n_classes, pretrained=True, trainable_blocks=0):
    model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT if pretrained else None)
    freeze(model)                                              # every parameter: requires_grad_(False)
    model.fc = nn.Linear(model.fc.in_features, n_classes)      # 512 -> n_classes, trainable
    for name in ["layer4", "layer3", "layer2", "layer1"][:trainable_blocks]:
        getattr(model, name).requires_grad_(True)              # unfreeze from the top down
    return model

model = build_transfer_model(101)
count_parameters(model)                              51813    of 11,228,325: 0.5% of the network trains

features, labels = extract_features(model, train_loader, device)   # fc swapped for nn.Identity for the pass
features.shape                                       torch.Size([3000, 512])

Fine-tuning with two learning rates

Once the head is good, unfreezing the top block, layer4, lets the network adapt its object-level features to dishes. Those weights are already good, so they should move gently, while the new head can still move fast. An optimizer accepts parameter groups, each with its own settings, and that is how both happen at once: the head at 1e-3, the backbone at 1e-4. Fine-tune everything at the head's rate and the pretrained features are overwritten in the first epoch, which the break-it step below will show you.

def param_groups(model, lr_head, lr_backbone):
    head = [p for n, p in model.named_parameters() if n.startswith("fc.") and p.requires_grad]
    backbone = [p for n, p in model.named_parameters() if not n.startswith("fc.") and p.requires_grad]
    return [{"params": head, "lr": lr_head}, {"params": backbone, "lr": lr_backbone}]

model = build_transfer_model(101, trainable_blocks=1)
count_parameters(model)                              8445541   layer4 plus the head
optimizer = torch.optim.Adam(param_groups(model, lr_head=1e-3, lr_backbone=1e-4))

Evaluating honestly

Accuracy is one number and a hundred classes hide inside it. A confusion matrix counts, for every true class, what the model called it: rows are truth, columns are predictions, the diagonal is what went right. From it come per-class accuracy (diagonal over row sums), which shows the classes the model cannot do, and the most-confused pairs, which show you what to look at: two dishes that are visually near-identical, or two classes with mislabelled data. Top-k accuracy asks whether the truth is among the k highest logits; for near-twins like pho and ramen, top-5 is the number papers quote, and the gap between top-1 and top-5 says how often the model is close but not exact.

cm = confusion_matrix(preds, y, n_classes=101)      tensor (101, 101), int64; cm.sum() == len(y)
per_class_accuracy(cm)                               tensor (101,) : diagonal / row sums
most_confused(cm, k=5)                               [(true, predicted, count), ...]   the pairs worth a look
top_k_accuracy(logits, y, k=5)                       a float; always ≥ top-1

  7. Break it on purpose: fine-tune everything at the head's learning rate

    build_transfer_model(20, trainable_blocks=4) with a single learning rate of 1e-3 for all 11 million parameters. Validation accuracy drops below the frozen-backbone result within an epoch or two: the pretrained features, which took a million images to learn, are wiped by large steps computed from three thousand. Pretrained weights are a resource; the small backbone learning rate is how you spend it slowly.

Common errors

RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn
You froze the model after replacing the head, so the new head is frozen too. Freeze first, then replace.
Accuracy is near chance even though the loss falls on the cached features
The validation images were not passed through weights.transforms(), or were normalized with different statistics. The backbone expects ImageNet normalization exactly.
Validation accuracy drops when fine-tuning starts
The backbone's learning rate is too high, or you fine-tune with model.train() on BatchNorm layers with tiny batches, which corrupts their running statistics. Lower the rate; consider keeping the backbone in eval mode while fine-tuning the top block.
ValueError: some parameters appear in more than one parameter group
param_groups put a parameter in both lists. Split on the name prefix fc. exactly, and skip frozen parameters.
RuntimeError: mat1 and mat2 shapes cannot be multiplied (64x512 and 2048x20)
The head was sized for a different backbone. ResNet-18 and -34 pool to 512; ResNet-50 and larger to 2048. Read model.fc.in_features instead of assuming.
Downloading the weights fails
Colab has internet; CI does not and must not. Tests use pretrained=False; if you wrote a test that needs the real weights, mark it slow.
