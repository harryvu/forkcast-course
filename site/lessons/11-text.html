Text as tensors

Part 3, Language. About 2 hours. GPU optional. You'll leave with the pipeline that turns a sentence into a tensor, the mask that keeps padding honest, and a sentiment model that reads Forkcast reviews.

Objectives

By the end of this lesson you can:

  1. Tokenize text and build a vocabulary with reserved ids for padding and unknown words, from the training set only.
  2. Encode reviews as id tensors, pad a batch to one length, and build the mask that marks the real tokens.
  3. Use nn.Embedding for words, with padding_idx, and pool a variable number of token vectors into one with a masked mean.
  4. Train a bag-of-embeddings sentiment classifier with the toolkit, and read every shape from (N, T) to logits.
  5. Say what the bag throws away, which is the problem Lesson 12 solves.

Where we are

Forkcast customers leave reviews, and the app wants to know, without a person reading each one, whether a review is happy or not: to flag a restaurant with a bad week, to surface the dish people love, to catch a rider problem early. Pictures became tensors in Lesson 7; today text does. The bundled file is a small templated corpus of delivery reviews so the tests run offline; the notebook trains the same model on hundreds of thousands of real Yelp reviews.

Tokens and ids

A model consumes numbers, so a review has to become a sequence of integers. Tokenizing splits the text into units, here lower-cased words and a few punctuation marks. A vocabulary assigns each distinct token an id, most frequent first, with two ids reserved: 0 for padding, 1 for any token that was not in the training reviews. Build the vocabulary from the training set only; a word that appears only in validation must map to <unk>, because that is exactly what will happen with a customer's review tomorrow.

tokenize("Great food, FAST delivery!")             ['great', 'food', ',', 'fast', 'delivery', '!']

vocab = Vocab([tokenize(t) for t in train_texts], min_freq=1)
len(vocab), vocab.itos[:6]                           (87, ['<pad>', '<unk>', '.', 'the', 'was', 'and'])   the templated corpus is tiny
ids = vocab.encode(tokenize("The pad thai was delicious and the delivery was late. Mixed feelings!"))
ids                                                  [3, 21, 22, 4, 57, 5, 3, 6, 4, 20, 2, 1, 1, 16]   two unknown words
vocab.decode(ids)[-4:]                               ['.', '<unk>', '<unk>', '!']

Padding and masks

Reviews have different lengths and tensors are rectangular. A batch is padded with id 0 to the length of its longest review, and a boolean mask records where the real tokens are. From here on, every operation that sums or averages over the token dimension must consult the mask, or the padding leaks into the result: a two-word review padded to twenty would have its meaning diluted ten-fold by zeros.

def pad_batch(sequences, pad_idx=0):
    ids = pad_sequence(sequences, batch_first=True, padding_value=pad_idx)   # (N, T)
    mask = ids != pad_idx                                                    # (N, T) bool
    return ids, mask

def collate_reviews(batch):                          # the DataLoader's collate_fn
    ids, labels = zip(*batch)
    padded, mask = pad_batch(list(ids))
    return padded, mask, torch.stack(labels)         # target last: the toolkit's convention

ids, mask, labels = next(iter(train_loader))
ids.shape, mask.shape, mask.sum(dim=1)[:4]           (torch.Size([32, 18]), torch.Size([32, 18]), tensor([17,  9, 15, 17]))

Lesson 6's DataLoader stacked items with its default collate, which only works when every item has the same shape. collate_fn is the hook for everything else: it receives the list of items and returns the batch, in whatever form the model wants. The toolkit's convention that the target comes last is what lets fit_v2 call model(ids, mask) without knowing anything about text.

Embeddings for words

This is Lesson 6's nn.Embedding again, with a vocabulary of words instead of taxi zones: a table with one learned row per id. Two details are new. padding_idx=0 keeps row 0 at zero and gives it no gradient, so padding contributes nothing even before the mask. And a review is many ids, so the lookup returns (N, T, D): one vector per token. To classify the review you need one vector per review, and the simplest way is to average the token vectors, over the real tokens only.

emb = self.embedding(ids)                            # (N, T, D)
m = mask.unsqueeze(-1).to(emb.dtype)                 # (N, T, 1): 1.0 on real tokens
pooled = (emb * m).sum(dim=1) / m.sum(dim=1).clamp_min(1.0)   # (N, D): divide by the real length, not by T

The model: a bag of embeddings

Embed, average, classify: the whole model. The average is called a bag because, like a bag of words, it forgets order: "the food was good, not the service" and "the service was good, not the food" produce the same vector. For sentiment that costs surprisingly little, since the words carry most of the signal, and the model trains in seconds. Lesson 12 is about what it costs when order matters.

class BagOfEmbeddings(nn.Module):
    def __init__(self, vocab_size, dim=64, hidden=64, n_classes=2):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, dim, padding_idx=0)
        self.head = nn.Sequential(nn.Linear(dim, hidden), nn.ReLU(), nn.Linear(hidden, n_classes))
    def forward(self, ids, mask):
        emb = self.embedding(ids)
        m = mask.unsqueeze(-1).to(emb.dtype)
        pooled = (emb * m).sum(dim=1) / m.sum(dim=1).clamp_min(1.0)
        return self.head(pooled)

torch.manual_seed(0)
model = BagOfEmbeddings(len(vocab), dim=32, hidden=32)
count_parameters(model)                              3906
history = train.fit_v2(model, train_loader, val_loader, epochs=8, lr=3e-3, loss_fn=nn.CrossEntropyLoss())
[round(v, 3) for v in history["val"]]               [0.568, 0.263, 0.058, 0.017, 0.009, 0.005, 0.004, 0.003]

Templated reviews are, by construction, trivially separable, and the model reaches 100% on them in two epochs. Real reviews are not: expect a bag-of-embeddings model to land around 90% on Yelp polarity, which is remarkable for a model that does not know what order the words came in.

  8. Break it on purpose: drop the mask

    pooled_unmasked = emb.mean(dim=1)                    # divides by T, zeros included

    Replace the masked mean with a plain mean over T and retrain on Yelp. Accuracy falls, and short reviews fall hardest: a six-word rave padded to 200 becomes a vector 97% zero, indistinguishable from a six-word complaint. The mask is not a detail; it is how the model knows where the review ends.

Common errors

RuntimeError: stack expects each tensor to be equal size, but got [12] at entry 0 and [17] at entry 1
The loader used the default collate on variable-length reviews. Pass collate_fn=collate_reviews.
IndexError: index out of range in self
An id at or above len(vocab) reached the embedding. The model was built with a smaller vocabulary than the one used to encode, or a vocabulary was rebuilt after the model.
RuntimeError: The size of tensor a (64) must match the size of tensor b (18) at non-singleton dimension 2
The mask was multiplied without unsqueeze(-1): (N, T, D) times (N, T) does not broadcast; (N, T, 1) does. Lesson 0's rule.
Validation accuracy near 50% while training loss falls
Labels and reviews shuffled separately, or the validation reviews encoded with a different vocabulary than the training ones. One Vocab, built once, used everywhere.
Nearly every token is 1
min_freq too high for a small corpus, or you encoded raw strings instead of token lists (vocab.encode("hot") iterates the characters). Encode tokenize(text).
Loss is nan
A division by zero in the masked mean for an all-padding row. clamp_min(1.0) on the denominator; and check that no review tokenized to nothing.

Stretch

Replace the embedding plus masked mean with nn.EmbeddingBag(len(vocab), dim, mode="mean", padding_idx=0), which does both in one fused call, and compare speed and accuracy. Then try max pooling instead of the mean (set padded positions to a large negative number first) and look at which reviews each pooling gets right that the other gets wrong; max pooling finds the one decisive word, mean pooling weighs the whole review.
