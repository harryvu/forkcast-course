Where we are

Six lessons on deliveries that came out of a random number generator. Today they come out of a city. New York publishes every yellow-taxi trip: when it started, when it ended, how far it went, from which zone to which. A taxi ride is not a food delivery, but it has the same shape, a rider moving through traffic from here to there, and it is the closest public data to a delivery log. Three things change at once: the data has to be cleaned before it is believed, it no longer fits comfortably in one tensor you step on all at once, and two of its columns are not numbers at all but zone ids.

Real data has to be cleaned first

The repository bundles a small simulated file with the exact TLC columns, so the tests run offline; the notebook downloads a real month. Both go through the same function, clean_trips, which is provided and worth reading. It derives minutes from the two timestamps, hour and weekday from the pickup, fills missing passenger counts, maps zone ids outside 1 to 265 to 0 for "unknown", and then drops rows that cannot be real: zero distance, trips under a minute or over two hours. It prints what it removed, because a cleaning step that works silently is a cleaning step nobody checks.

Four columns are continuous and get normalized as before. Two, pu_zone and do_zone, are categories: zone 132 is not "more" than zone 43, it is JFK airport. Feeding them to the model as numbers would be a lie the model cannot detect. They get their own treatment below.

Dataset: one item at a time

A Dataset is a class with two methods: __len__ says how many items there are, and __getitem__(i) returns item i. That is the whole contract, and it is what lets PyTorch batch anything, tables, images, text, the same way. For trips, an item is a tuple: the four continuous features, the two zone ids as int64, and the minutes. Convert the whole frame to tensors once in __init__, so __getitem__ is a plain index.

class TripsDataset(Dataset):
    def __init__(self, frame, normalizer=None):
        cont = torch.tensor(frame[CONTINUOUS].values, dtype=torch.float32)        # (N, 4)
        self.cont = normalizer.transform(cont) if normalizer is not None else cont
        self.cat = torch.tensor(frame[CATEGORICAL].values, dtype=torch.long)       # (N, 2): indices, so int64
        self.target = torch.tensor(frame[TARGET].values, dtype=torch.float32)       # (N,)
    def __len__(self):
        return len(self.target)
    def __getitem__(self, i):
        return self.cont[i], self.cat[i], self.target[i]

DataLoader: items become batches

A DataLoader wraps a dataset and hands out batches. Each epoch it decides an order of the indices (a fresh random one when shuffle=True), walks that order batch_size items at a time, fetches each item with __getitem__, and stacks the tuples field by field, so a batch of trips is a tuple of three tensors with a leading batch dimension. drop_last=True throws away the short final batch, which keeps every training step the same size; the validation loader keeps it, because every row must be scored. Step through one.

train_loader = DataLoader(TripsDataset(train_frame, norm), batch_size=256, shuffle=True, drop_last=True)
val_loader   = DataLoader(TripsDataset(val_frame, norm),   batch_size=256, shuffle=False)
len(train_loader), len(val_loader)                   (15, 4)      4095 // 256 = 15 full batches; 878 rows -> 4 batches, the last one short
cont, cat, minutes = next(iter(train_loader))
cont.shape, cat.shape, minutes.shape                 (torch.Size([256, 4]), torch.Size([256, 2]), torch.Size([256]))
cat.dtype                                            torch.int64

Mini-batches change the loop, a little

Until now one epoch was one gradient step on all the data. With a loader, one epoch is len(loader) steps, each on a batch. Each step's gradient is an estimate from 256 trips rather than the exact gradient over all 4095, so the loss curve gets noisier, and training gets much faster per pass through the data, because fifteen updates happen where one did. Beyond speed, there is no choice: a month of real trips is three million rows, and a step over all of them at once would not fit in memory.

The toolkit grows loader versions of its functions. train_one_epoch_loader loops over the batches, and inside the loop the five lines are the ones from Lesson 3. Two details: a batch is a tuple whose last element is the target, so *inputs, target = batch and model(*inputs) work for one input or two; and the epoch's loss is the mean over rows, not over batches, so each batch's loss is weighted by its size. A device argument moves each batch before use; it is "cpu" today and does nothing, and in Lesson 8 it is the only thing that changes.

def train_one_epoch_loader(model, loader, optimizer, loss_fn, device="cpu"):
    model.train()
    total, seen = 0.0, 0
    for batch in loader:
        *inputs, target = batch
        inputs, target = [x.to(device) for x in inputs], target.to(device)
        optimizer.zero_grad()
        loss = loss_fn(model(*inputs), target)
        loss.backward()
        optimizer.step()
        total += loss.item() * len(target)          # weighted: the last batch may be smaller
        seen += len(target)
    return total / seen

Embeddings: a learned table for categories

The honest way to feed a category to a model is one-hot: a vector of 266 zeros with a single 1. The first linear layer then multiplies that vector by a (266, 8) weight matrix, and multiplying a one-hot vector by a matrix simply selects one row of it. nn.Embedding(266, 8) is that matrix with the multiplication skipped: give it an index, get a row of 8 learned numbers. The rows are parameters like any other, trained by the same backward pass, so zones that affect trip time the same way drift toward similar rows, with nobody telling the model what an airport is.

class TabularNet(nn.Module):
    def __init__(self, n_continuous, zone_vocab=266, emb_dim=8, hidden=(64, 64)):
        super().__init__()
        self.pu = nn.Embedding(zone_vocab, emb_dim)       # weight (266, 8)
        self.do = nn.Embedding(zone_vocab, emb_dim)
        self.mlp = MLP(n_continuous + 2 * emb_dim, hidden) # Lesson 4's MLP, input width 4 + 8 + 8
    def forward(self, x_cont, x_cat):                     # (N, 4), (N, 2) int64 -> (N,)
        features = torch.cat([x_cont, self.pu(x_cat[:, 0]), self.do(x_cat[:, 1])], dim=1)   # (N, 20)
        return self.mlp(features)

model = TabularNet(4)
count_parameters(model)                              9825     of which 2 × 266 × 8 = 4256 live in the two tables

The size of the table's rows, emb_dim, is a choice: too small and zones cannot be told apart, too large and each zone's few trips cannot pin its row down. Eight is a reasonable default for a few hundred categories. Lesson 11 uses the identical layer for words, with a vocabulary of thirty thousand and rows of a few hundred numbers.

Common errors

RuntimeError: Expected tensor for argument #1 'indices' to have one of the following scalar types: Long, Int; but got torch.FloatTensor
Zone ids reached the embedding as floats. Build the categorical tensor with dtype=torch.long and keep it out of the Normalizer.
IndexError: index out of range in self
An index equal to or above the vocabulary size. Zone ids run 1 to 265 and unknowns are mapped to 0, so the table needs 266 rows; check clean_trips ran.
TypeError: forward() missing 1 required positional argument: 'x_cat'
The loader yields three tensors and the loop passed only the first. Use *inputs, target = batch and model(*inputs).
Training loss per epoch looks right, validation loss is nan
The validation frame was normalized with a Normalizer fitted on a column that was constant in its own data (std 0) or not fitted at all. Fit once on the training frame and pass that one object to both datasets.
The last training batch has a different size and a shape assertion fails
Set drop_last=True on the training loader, or write code that does not assume a fixed batch size, which is the better habit.
Validation loss stuck near the variance of the target
shuffle=False on a training file that is sorted by time or zone. Shuffle the training loader.
