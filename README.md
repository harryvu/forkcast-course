# Forkcast course: deep learning and PyTorch by building

[![Reference solutions](https://github.com/harryvu/forkcast-course/actions/workflows/reference.yml/badge.svg)](https://github.com/harryvu/forkcast-course/actions/workflows/reference.yml)

An interactive, project-based course for developers who know Python and nothing about matrices yet. Over eighteen lessons you build the machine-learning backend of **Forkcast**, a fictional food-delivery app: a delivery-time predictor, a dish-photo classifier, a review reader, a recommender, all behind one API.

The whole course is one interactive HTML page: every lesson is a section of `docs/index.html`, with live diagrams, questions, step-by-step build instructions and a **definition of done**, commands whose output tells you whether you met the objectives. Each lesson also has a thin Colab notebook where the code runs.

**Course site:** https://harryvu.github.io/forkcast-course/

## First-time setup for the course owner

The repository on GitHub starts empty; the course files are pushed from this folder once:

```
cd forkcast-course                       # the unzipped folder
git init -b main
git add -A
git commit -m "Forkcast course"
git remote add origin https://github.com/harryvu/forkcast-course.git
git push -u origin main
```

Then, on GitHub: *Settings → Template repository* (tick it, so students get a one-click copy and the student
workflow skips itself on this repository), and *Settings → Pages → Source: GitHub Actions* (the site deploys on
the next push that touches `docs/`). The Colab buttons and repository links on the site are built from
`site/assets/js/config.js`, which is already set to `harryvu/forkcast-course`; change it and run `make site`
if the repository moves.

## For students

1. Click **Use this template** at the top of this page and create your own `forkcast-course` repository (public is fine).
2. Open the course site and start with [Lesson 0](https://harryvu.github.io/forkcast-course/#lesson-00). It walks you through opening the notebook in Colab, cloning *your* repository there, and running the first checks.
3. Each lesson's notebook writes that lesson's starter files into `forkcast/` (also available as `make start-NN`), and you fill them in. Tests for lessons you have not reached are skipped automatically, so the **DoD checks** workflow is green exactly when your current lesson is done.

Fell behind or broke something? Every lesson's reference solution is in `solutions/`. `make catchup-03` copies the Lesson 3 solution into `forkcast/`, which is exactly the starting point for Lesson 4.

## How the repository is organised

```
docs/index.html       the whole course as one self-contained page (built; GitHub Pages serves docs/)
site/                 the sources that build it
  template.html       page shell
  home.html           syllabus and progress view
  lessons/            one <article> fragment per lesson
  assets/             shared CSS, the widget library, config.js
forkcast/             the Python package you grow, lesson by lesson
tests/                definition-of-done tests, test_00.py, test_01.py, ...
notebooks/            one Colab notebook per lesson (generated by tools/make_notebooks.py)
starters/             each lesson's starting files (what its notebook writes), mirroring forkcast/
solutions/            reference solutions, one folder per lesson, mirroring forkcast/
tools/                build_site.py (assembles docs/index.html), link checker, notebook generator
.github/workflows/    ci.yml (student DoD), reference.yml (solutions + site), pages.yml (deploy)
```

Useful commands, all runnable from a Colab cell with a leading `!`:

```
make env            # python / torch version and the device found
make check-00       # one lesson's definition-of-done tests
make check-fast     # every fast test so far (what CI runs)
make catchup-00     # copy a lesson's reference solution into forkcast/
make site           # rebuild docs/index.html from site/
make site-check     # verify every internal link in the built page resolves
```

## Running locally

```
python -m venv .venv && source .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu   # or a CUDA build
pip install -e ".[dev]"
pytest -m fast
```

Lessons 0 to 6 run comfortably on a laptop CPU. From Lesson 7 the pages assume a GPU runtime in Colab.

## For maintainers

- **Site.** Edit sources under `site/`, run `make site`, and commit the rebuilt `docs/index.html`; the reference workflow fails if the committed build is stale. Pushes that touch `docs/` deploy to GitHub Pages through `pages.yml`. One-time setup: *Settings → Pages → Source: GitHub Actions*. Lessons are addressed by hash: `/#lesson-03`, or `/#lesson-03/build` for a section.
- **Template.** Mark the repository as a template (*Settings → Template repository*) so students get a one-click copy. The student workflow `ci.yml` skips itself on the template repository, where the starter code is intentionally unfinished.
- **Config.** After creating the repository, set `repo` in `site/assets/js/config.js`, run `make site`, and replace `harryvu` in this README. That value identifies the course's own repository (the *Use this template* link). Students enter their own GitHub user on the site itself (topbar button, or the setup box on the home page and in Lesson 0); every *Open in Colab* and repository link is rebuilt from it and remembered in their browser, so the notebooks open from their copy.
- **Notebooks.** Edit `tools/make_notebooks.py`, not the `.ipynb` files; the `%%writefile` cells are generated from the real starter modules so they cannot drift.
- **Adding a lesson.** Add `site/lessons/NN-slug.html` (an `<article data-lesson="NN">` whose section ids are prefixed `lNN-`), the starter files in `starters/lessonNN/forkcast/` (the previous lesson's solution plus the new TODOs), `tests/test_NN.py` guarded with `lesson_module(...)` so it skips until started, `solutions/lessonNN/forkcast/...`, a notebook builder in `tools/make_notebooks.py`, link it from `site/home.html` and the previous lesson's footer, then `make site`. `forkcast/` on `main` holds only the Lesson 0 files and the provided `data.py`.
